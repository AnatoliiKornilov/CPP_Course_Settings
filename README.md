# Правила по оформлению и сдаче задач 

1. Создайте приватный репозиторий на GitHub. Пригласите в репозиторий вашего ревьюера. Скиньте ссылку на свой репозиторий в таблицу, чтобы ревьюер не искал каждый раз ваш репозиторий. 

2. Следуйте фиксированной структуре расположения файлов. Для каждого модуля заводите свою папку с названием в виде номера модуля, для каждой задачи заводите свою папку внутри соответствующего модуля с названием в виде номера задачи. Например все файлы для решения задачи 02.01 будут лежать по пути 02/02.01/название_файла. Все соответствующие файлы для решения задачи можно называть на своё усмотрение, но настоятельно рекомендуется нормальные человеческие названия файлов, например, sort.cpp или run_script.sh. (Почему папка? Потому что для сдачи задачи может потребоваться много файлов. Такая система позволяет называть файлы человеческими именами и держать их в одном понятном месте).

3. Обязательно выполните все шаги из файла [instruction.md](instruction.md) для настройки кодстайла и линтера.

4. Для ознакомления с базовыми правилами кодстайла изучите файл [codestyle_demo.cpp](codestyle_demo.cpp).

5. К каждой задаче помимо файлов с кодом в соответствующую папку обязательно кладите sh-файл с инструкциями, как собирать и запускать решение. Это нужно, чтобы ревьюер не гадал, какие флаги нужно прописывать в каждом случае. Если захотите использовать CMake, то помимо CMakeLists.txt также добавляйте sh-файл, в котором будут команды для сборки с помощью CMake и запуска.

6. Держите ваш репозиторий на GitHub чистым, не забудьте про .gitignore и добавляйте туда файлы с настройками IDE (например, папку .vscode), а также все исполняемые файлы, которые у вас остаются после компиляции (проще всего создать в корне папку build, каждый раз класть исполняемые файлы туда, а саму папку в .gitignore, но это непринципиально) и прочие файлы, которые не относятся к настройкам удалённого репозитория и решениям задач. 

7. Для сдачи каждого домашнего задания создавайте новую ветку с названием HW_XX.XX-YY.YY, где XX.XX - номер первой задачи из домашнего задания на неделю, YY.YY - последней. Далее открывайте Pull Request в main и поставьте соответствующего ассистента в ревьюеры. Когда баллы по домашнему заданию будут зафиксированы, PR можно вливать в main.

8. Также не забывайте соблюдать все требования из задачника и условия задачи.

9. Для ознакомления с форматой сданной задачи в этом репозитории есть задача номер 00.00, где печатется Hello, World!
